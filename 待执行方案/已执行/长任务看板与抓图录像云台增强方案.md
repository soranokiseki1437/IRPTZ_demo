# 长任务看板与抓图/录像/帧率/云台增强方案

> **归档状态（2026-11-10）**：LT-01~LT-07 代码已全部落地，Debug 构建通过（exit 0）。硬件相关验收（抓图落盘、MP4 可播放、FPS 数值、速度 1~7 手感、巡航圈时）转入看板 LT-12 真机回归。

## 1. 概要

本方案一次性交付两部分内容：

1. **长任务看板**：既生成 `待执行方案/长任务看板.md`，也在应用内新增可置顶、可拖拽的悬浮看板窗口；已执行的方案移入 `待执行方案/已执行/`。
2. **功能修复与增强**：
   - 抓图/定时抓图保存修复（路径迁移、JPEG 质量参数、定时器翻倍 Bug）
   - 录像保存修复，并改为**原始码流直封装 MP4**（不再解码重编码，画质与设备主码流一致）
   - 画框右下角实时帧率叠层
   - 云台速度改为设备实际支持的 1~7 档，并在按住方向键期间实时生效
   - 循环 360° 自动巡航（按当前速度连续旋转，按设定单圈时间计圈，手动停止）
   - SDK 其他功能盘点，形成后续长任务清单

已确认的产品决策：

- 看板形式：**Markdown 文件 + 应用内悬浮置顶看板，两者都要**
- 自动巡航：**循环 360° 巡航**，直到手动停止
- 录像清晰度：**原始码流直封装（remux）**

## 3. 总体设计

### 3.1 看板

- `待执行方案/长任务看板.md` 作为唯一任务源，固定结构：
  - `## 待执行`、`## 进行中`、`## 已完成` 三个分区
  - 每个分区一张 Markdown 表格：`| ID | 任务 | 优先级 | 验收标准 | 关联方案 |`
- 应用内 `TaskBoardWindow` 读取该文件，解析三个分区并渲染成三列卡片看板；只读展示，提供“刷新”按钮。
- 看板窗口：无边框、半透明深色、可拖拽、`Qt::WindowStaysOnTopHint` 置顶、可关闭/隐藏；位置和置顶状态用 QSettings 保存。
- 主界面菜单“菜单”下新增“长任务看板”动作，用于显示/隐藏悬浮看板。
- 文件查找顺序：`applicationDirPath()/待执行方案/长任务看板.md` → 逐级向上最多 4 层 → `QDir::currentPath()/待执行方案/长任务看板.md`。
- 已执行方案移入 `待执行方案/已执行/`；旧方案 `云台延迟修复与优化方案.md` 按代码实际状态归档（P0 与 P1-3 已落地，P1-1/P1-2/P1-4/P2 转入看板待执行）。

### 3.2 抓图

- `JPEGPARA` 改为 `{ wPicSize = 0xFF, wPicQuality = qBound(0, quality, 2) }`，使用当前码流原始分辨率与合法质量档。
- UI 质量控件改为 0~2 三档（0 最好、1 较好、2 一般），默认 1；配置旧值 >2 自动迁移为 1。
- 定时抓图只传秒数，由 CaptureManager 统一乘 1000。
- 保存路径统一为绝对路径；加载配置时把旧项目路径（包含 `RGB_PTZ_demo`）迁移到当前 `applicationDirPath()/captures`。
- 抓图成功后状态栏和日志显示**完整文件路径**，历史列表保留文件名。

### 3.3 录像

- 改为 remux：不再解码、不再编码，直接把 RTSP 收到的 H.264/H.265 原始包写入 MP4。
- `RecordThread` 负责：等待关键帧 → 写 MP4 头（复制源 `AVCodecParameters` 与 extradata）→ 按源 PTS/DTS 写入 → 停止时写 trailer。
- H.265 流设置 `codec_tag = 'hvc1'`，提升播放器兼容性。
- 录像开始后最多等待一个 GOP；停止时若从未收到关键帧，删除空文件并报错。
- RTSP 断流/重连时主动停止当前录像并提示，避免 PTS 回绕产生损坏 MP4。
- 录像路径从配置读写，默认 `applicationDirPath()/videos`，选择后立即持久化。
- 录像错误时 UI 必须复位，不能停留在“录像中”。

### 3.4 帧率

- 新增 `QLabel` 作为 `rgbLabelImage` 的子控件，叠在**实际视频画面右下角**（考虑 KeepAspectRatio 产生的黑边偏移）。
- 每收到一帧计数；每 ≥1000ms 计算一次 FPS 并刷新文本，如 `FPS 19.8`。
- 不把文字画进 QPixmap，避免每帧触发 pixmap 深拷贝。
- 断流时隐藏或显示 `FPS --`；重连后重新统计。
- `labelVideoResolution` 增加码流信息：`分辨率: 1280×720 · H.264 · 25fps`。

### 3.5 云台速度

- UI 速度控件改为 **1~7 档**（QDoubleSpinBox，decimals=0，step=1，默认 4，tooltip“1=最慢，7=最快”）。
- 增加 `levelToRawSpeed()`：将 1~7 映射到现有 0~63 原始速度区间（1→1，7→63，线性），保持跟踪控制使用的 0~63 语义不变。
- `NetPtzController` 默认 SDK 速度范围由 1~63 改为 **1~7**；`mapPelcoSpeed` 仍按比例映射，因此 UI 1~7 最终稳定落到设备 1~7。
- 按住方向键期间修改速度：立即更新 `m_ptzManualHSpeed/VSpeed` 并重发运动指令，不松开也能生效。
- 记录方向轴（水平/垂直/对角），速度变化时按当前方向重新计算主/次轴速度。
- 保留 500ms 看门狗与 200ms 周期重发。
- 若实测 1~7 仍无速度差异，按 241211 Demo 的调用方式做 A/B：先对比 `SV_NET_DEV_PTZControlWithSpeed_EX` 与 `SV_NET_DEV_PTZControlWithSpeed`，仍无效则用 `SV_NET_DEV_TransPTZ_Other` 发送标准 Pelco-D 帧并保留日志；该兜底只在实测失败时启用。

### 3.6 自动巡航

- 在“云台控制”分组内新增“自动巡航”子分组：
  - `spinCruiseSeconds`：单圈时间，5~3600 秒，默认 60
  - `btnCruiseStart`：开始巡航
  - `btnCruiseStop`：停止巡航
  - `labelCruiseStatus`：显示“未巡航 / 循环巡航中 · 第 N 圈”
- 行为：
  1. 读取当前 UI 速度档并转换为原始速度。
  2. 调用现有 `startManualMove(0x02, rawSpeed, 0)` 持续 PAN_RIGHT；200ms 周期重发维持运动并喂看门狗。
  3. 启动单圈计时器；每满 `spinCruiseSeconds` 秒圈数 +1，并重新计时，**不停转**，实现循环 360°。
  4. 手动“停止巡航”、急停、方向键/预置位操作、RTSP 断开、窗口关闭均停止巡航。
  5. 巡航期间暂停测温轮询，停止后按原状态恢复。
- 由于设备没有可靠的绝对角度回读，360° 按“当前速度下的单圈时间”近似；界面明确显示单圈秒数与圈数，便于现场校准。

### 4.4 录像 remux

- `rtspsource.h/cpp`
  - 新增结构体：
    ```cpp
    struct EncodedPacket {
        QByteArray data;
        int64_t pts = AV_NOPTS_VALUE;
        int64_t dts = AV_NOPTS_VALUE;
        bool key = false;
    };
    ```
  - RTSP 连接成功后保留 `par` 的深拷贝、`time_base`、`avg_frame_rate`，调用 `m_recorder->setSourceCodecParameters(...)`。
  - 解码器仍使用“带 extradata 的关键帧 payload”；录像改为推送**原始包** + pts/dts/key。
  - 新增 `streamInfo(QString)` 信号，内容包含编码格式、分辨率、帧率。
  - `av_read_frame` 失败且正在录像时，调用 `m_recorder->abortRecording("RTSP 连接中断")`，避免断流后继续写坏文件。
- `recordthread.h/cpp`（重写）
  - 删除 VideoDecoder/libx264 编解码路径，同时删除 `setEncType()` 接口（原调用方在 `DeviceManager::onRtspStreamConnected()`，一并移除）。
  - 队列改为 `ThreadSafeQueue<EncodedPacket>`，容量提高到 300 帧。
  - `initRecord()` 内必须先调用 `m_dataQueue.reset()`：`ThreadSafeQueue::stop()` 不可逆，否则第二次录像线程会立即退出。
  - 新增 `setSourceCodecParameters(const AVCodecParameters *, AVRational, AVRational)`，内部加 `QMutex` 深拷贝。
  - `initRecord(const QString &filePath)`：重置状态、创建目录、校验 codecpar。
  - `run()`：
    - `m_running = true`
    - 等待第一个关键帧后才 `avformat_alloc_output_context2("mp4")`、`avcodec_parameters_copy`、`avformat_write_header`
    - 每包新建 `AVPacket`，拷贝数据，`av_packet_rescale_ts(srcTimeBase, outStream->time_base)`，`av_interleaved_write_frame`
    - H.265 设置 `codec_tag = MKTAG('h','v','c','1')`
    - 停止/断流时 `av_write_trailer`、关闭文件；若从未写头则删除空文件并报错
  - `stopRecord()`：`m_running=false` + 入队空包；`abortRecording(reason)`：记录原因、停止并通知。
  - `recordFinished(filePath)` 只在文件成功收尾后发出。

### 4.10 关键实现细节（执行时不再二次决策）

**录像 remux 写包**

- 输出流：`avformat_new_stream` 后 `avcodec_parameters_copy(out->codecpar, srcPar)`，`out->codecpar->codec_tag = 0`（H.264）或 `MKTAG('h','v','c','1')`（H.265）。
- 写包前设置：`pkt->stream_index = out->index; pkt->flags = key ? AV_PKT_FLAG_KEY : 0; pkt->pos = -1;` 再 `av_packet_rescale_ts(pkt, srcTimeBase, out->time_base)`。
- 首包必须是关键帧；关键帧之前收到的包直接丢弃，且不计入“录像时长”。
- `stopRecord()` 只置位并入队空包，不做阻塞等待；`abortRecording(reason)` 由 RTSP 线程调用，等价于“置位 + 记录原因”，不 `wait()`。
- `run()` 收尾顺序：`av_write_trailer` → `avio_closep` → `avformat_free_context`；若从未写头（没等到关键帧），删除 0 字节文件并发 `errorOccurred("未收到关键帧")`。
- `RecordThread` 对外仍用两个信号：`recordFinished(filePath)`（成功）、`errorOccurred(reason)`（失败）；两者互斥，只发一个。

**DeviceManager 状态机**

- `startRecord()`：`m_isRecording` 先置 false → `initRecord()` → `m_recordThread->start()` → 成功后 `m_isRecording=true` 并 `emit recordStarted()`；任一步失败回滚、`wait(1000)`、返回 false。
- `stopRecord()`：`m_isRecording=false` 后调用 `m_recordThread->stopRecord()`，不直接发 `recordStopped`。
- `onRecordFinished()` / `onRecordError()` 都必须先 `m_isRecording=false`，再分别发 `recordStopped` / `recordFailed`。
- 新增 `void recordFailed(const QString &)`、`void streamInfo(const QString &)` 两个信号；`RtspSource::streamInfo` 连接到 `DeviceManager` 后转发给 MainWindow。

**FPS 叠层几何**

- `m_fpsLabel` 父对象为 `ui->rgbLabelImage`，`setAttribute(Qt::WA_TransparentForMouseEvents)`，样式固定为半透明黑底 + 亮绿等宽字体 + `padding: 2px 6px`。
- 每次 `setPixmap` 后按 `ui->rgbLabelImage->size()` 与 `m_scaledPixmap.size()` 计算偏移：`x = (lw - pw)/2 + pw - labelW - 10`，`y = (lh - ph)/2 + ph - labelH - 10`；偏移为负时钳位到 10。
- 统计窗口固定 1000ms；`displayImage()` 每帧 `++m_fpsFrameCount`，到期计算 `fps = frames * 1000.0 / elapsed`，保留 1 位小数。
- `onConnectionStatusChanged(false)` 与 `streamStarted(false)` 时 `m_fpsLabel->hide()` 并清零。

**看板窗口**

- QSettings 键：`taskboard/geometry`（QByteArray）、`taskboard/onTop`（bool，默认 true）。
- 解析规则：只认以 `## ` 开头的三个标题（待执行/进行中/已完成）；表格行按 `|` 分割，跳过表头与 `---` 分隔行；空行或列数不足 5 的行忽略。
- 卡片文本：`ID + 任务`；优先级用颜色区分（高=红、中=黄、低=灰）；tooltip 显示验收标准与关联方案。
- 文件定位：`applicationDirPath()/待执行方案/长任务看板.md`，找不到则最多向上 4 层查找，最后回退 `QDir::currentPath()`。

## 5. 假设与决策

1. **360° 是时间近似**：设备 `GetPtzPosition` 无可靠绝对角度回读（现有代码已降级处理），因此自动巡航按“当前速度 + 单圈时间”计圈，不承诺闭环角度精度；现场可调整单圈秒数校准。
2. **速度档位按 1~7**：依据 241211 Demo `V1.3.0build` 的 `^([1-7])$` 校验和界面速度输入；`NetPtzController` 保留可配置范围，后续换设备可调整。
3. **录像采用 remux**：设备 RTSP 主码流本身即为原始画质；直封装不再引入二次压缩，CPU 占用显著下降。
4. **录像从下一个关键帧开始**：开始录像前最多等待一个 GOP，保证 MP4 首帧可解码。
5. **RTSP 重连停止录像**：避免 PTS 重置导致文件损坏；重连后由用户重新开始录像。
6. **旧方案归档为已执行**：代码中 P0（单飞测温、轮询降频、看门狗）与 P1-3 已落地；未完成的 P1-1/P1-2/P1-4/P2 不丢失，转入看板 LT-09~LT-11。
7. **看板只读**：应用内看板不直接编辑 Markdown，状态由方案执行时更新文件并刷新；避免两套数据源不一致。
8. **不改变现有测温/跟踪/预置位/镜头逻辑**，只增加速度、巡航、帧率和录像链路。
